## 评估揭示了什么

- 相近 QA 得分可以对应不同的执行画像：LiveCC 与 MOSS-Preview 的准确率都接近
  65%，但完成率、响应时延和观测到的 token 画像不同。
- 相近 Proactive 质量可以隐藏不同的响应选择行为：MOSS-VL 与 AURA 的窗口内
  准确率为 8.05% 和 7.92%；MOSS-VL 的误报率更低（41.1% 对 59.1%），观测到的
  中位延迟也更短。
- JoyAI 的窗口内准确率为 17.08%，其评测边界是包含记忆和调度组件的端到端系统，
  应在此边界下理解。
- MiniCPM-O 原生 duplex 是诊断接口条件：QA 准确率为 2.40%、无效输出为 93.52%，
  Proactive 窗口内准确率为 0.51%，延迟首 token 覆盖率为 24.6%。它不是从历史轮询
  运行推导出来的。

这些结果支持分别报告质量、及时性、响应选择行为、工作量和执行可靠性。

## QA 结果

QA **Recoverable Accuracy** 接受一个明确且唯一的选项标签，包括答案引导语或以标签
开头的选项文本。解析前移除隐藏思考。两个不同标签、无标签散文和普通冠词均无效。
该报告指标与软件默认严格解析器分开；论文兼容评分 profile 会显式区分二者。

响应时延从 Evaluation Core 收到问题到收到完整回答计算，包括问题激活后的必要历史处理、
输入准备、排队和生成，不等同于 TTFT。提交图像和输出 token 是各配置边界下的观测总量。

## Proactive 结果

**窗口内准确率**在全部 1,270 个目标窗口上计算，包含漏答和失败，并保留内容部分分。
**中位响应延迟**只统计已回答且观测到首 token 的窗口；snapshot 给出观测首 token 和已回答计数。
**误报率**按全局 response episode 计算：响应开始时没有任何有效窗口且之后仍有有效窗口时才进入
分子，最后窗口之后的尾部 episode 不进入分子。**漏报率**按目标窗口计算：没有分配响应才算漏报，
错误但已分配的响应不算漏报。

## 如何解释与复现

报告评估特定的模型、adapter 和系统配置。部分运行采用更长执行容差，
再统一按 W=5 重新评分，因此相同评分总体不意味着实际执行输入预算完全相同。
ThinkStream 受测配置存在末尾处理块提交限制；
JoyAI 对应受测配置，而不是完整配置下重新推理的结果。
MiniCPM-O native duplex 是带有明确时延覆盖率限定的诊断行；不可用的补充字段继续缺失。

线索充分子集仅有 10 个视频、48 个窗口，动作完成子集则有 319 个窗口。
Judge 校准为初步证据：分层抽样的 36 个样本中有 30 个二元判断一致，
不能视为总体可靠性保证；仅凭文本也无法核验视觉依据。
